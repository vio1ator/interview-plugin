# PRD Re-interview

Read the existing PRD, then interview me for changes, additions, and refinements using the AskUserQuestion tool.

First, read the current PRD: @$ARGUMENTS

## Interview Process

After reading the existing PRD:

1. **Acknowledge what exists**: Briefly summarize the current PRD to show understanding

2. **Identify areas to explore**: Use the AskUserQuestion tool to ask about:
   - **New features or capabilities**: What should be added?
   - **Changes to existing features**: What should be modified?
   - **Updated requirements**: Have technical or business constraints changed?
   - **Refined metrics**: Are success metrics still relevant?
   - **Market shifts**: Have competitors, users, or market conditions changed?
   - **Technical learnings**: What have we learned that impacts the PRD?
   - **Removed items**: What should be deprecated or removed?

3. **Adaptive questioning**: Start broad about what's changed, then drill into specifics based on my responses

4. **Be thorough but efficient**: Don't re-ask about things that haven't changed. Focus the interview on areas that need updates.

## Quality Standards

- Ask non-obvious questions that reveal important updates
- Challenge assumptions about existing requirements
- Explore implications of changes on other parts of the PRD
- Consider whether the structure and organization still makes sense

## Output

After the interview is complete, update and write the revised PRD to: @$ARGUMENTS

Maintain clear markdown formatting and ensure all sections are consistent and complete.
