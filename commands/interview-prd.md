# PRD Interview

Interview me to create a Product Requirements Document (PRD) using the AskUserQuestion tool. Use an adaptive questioning approach - start broad and drill deeper based on my responses.

## PRD Structure

Build a lean PRD with these sections:

### 1. Problem Statement
- What problem are we solving?
- Who experiences this problem?
- Why is this problem worth solving now?
- What are the pain points or gaps in current solutions?

### 2. Proposed Solution
- High-level product vision
- Core value proposition
- Key features and capabilities
- Differentiation from alternatives

### 3. Success Metrics
- Primary success metrics (KPIs, OKRs)
- Secondary metrics
- How will we measure success?
- What are the targets or benchmarks?

### 4. Key Requirements
- **Functional requirements**: What must the product do?
- **Non-functional requirements**: Performance, security, scalability, reliability
- **Technical constraints**: Platforms, technologies, dependencies
- **User experience**: Key user journeys and interactions

## Interview Approach

**Start broad**, then adapt based on responses:
- If I'm uncertain, drill into specifics with follow-up questions
- If I have clear answers, move to the next section efficiently
- Ask non-obvious questions that reveal hidden requirements or risks
- Challenge assumptions gently to uncover edge cases
- Explore technical feasibility and constraints
- Consider user experience and go-to-market implications

## Quality Standards

Make questions insightful and thought-provoking, not obvious. Continue interviewing until the PRD is comprehensive and complete.

## Output

After the interview is complete, write the full PRD to: @$ARGUMENTS

Use clear markdown formatting with:
- Headers for each section
- Bullet points for lists
- Tables where appropriate (e.g., metrics, requirements)
- Concise but complete information
